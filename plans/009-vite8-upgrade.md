## Why this matters

`npm audit` reports a **dev-server-only** moderate advisory
([GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)) in the
esbuild version bundled by Vite 5. It has **zero impact on the shipped app**
(`npm audit --omit=dev` → 0), and the only fix is a major Vite upgrade. The
maintainer has chosen to clear it anyway. The upgrade is contained: bump Vite and
the React plugin to their current majors; our `vite.config.js` uses only stable
APIs, and local Node 22.13 satisfies Vite 8's engine requirement.

## Scope

**In scope**:

- `frontend/package-lock.json` (regenerated by `npm install`)

## Steps

### Step 1 — Bump Vite and the React plugin
From `frontend/`, run:
`npm install -D vite@^8.3.4 @vitejs/plugin-react@^6.1.2`
This updates `package.json` and `package-lock.json` and installs the new versions.

**Verify**: `npx vite --version` → `vite/8.*`; `package.json` shows
`"vite": "^8.3.4"` and `"@vitejs/plugin-react": "^6.1.2"`.

### Step 2 — Confirm the advisory is cleared
**Verify**: `npm audit` → `found 0 vulnerabilities`.
(If it still reports vulnerabilities, STOP and report the advisory — do not run
`npm audit fix --force`.)

### Step 3 — Build with Vite 8
**Verify**: `npm run build` → exits 0 and prints the `dist/…` asset lines;
`frontend/dist/index.html` exists.

If the build fails:
- If the error is a known Vite 8 migration item with a documented one-line fix in
  `vite.config.js` (e.g. a renamed option), apply exactly that and note it.
- If it is anything else (app-code error, plugin incompatibility, an error you
  cannot resolve from the official Vite 8 migration guide), STOP and report with
  the full error — do NOT downgrade, patch app source, or guess.
