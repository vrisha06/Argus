## Open issues noted during audit (debugged)

Both confirmed via reproduction and now covered by **plan 004**. Repro commands
retained for reference:

- **`i++` / `--` unsupported in the parser.** The lexer tokenises `++`/`--`
  (`lexer.py:_OPS`) but `parser.py` never consumes them, so idiomatic
  `for (i=0; i<n; i++)` loops fail with `expected RPAREN, got '++'`. Workaround:
  `i = i + 1`. `for` is in the PRD subset, so this is a real usability gap.
  Repro: `printf 'int main(){int i; for(i=0;i<3;i++){} return 0;}' > /tmp/i.c && python -m securecompile_x.cli /tmp/i.c`
- **Chained assignment `a = b = c` silently miscompiles.** `parser.py` builds a
  nested `_AssignExpr` as the value, but `ir.py:_expr` has no case for it, so the
  inner `b = c` is never emitted and `a` receives a `None` operand — no error,
  no diagnostic. Risk: silent taint false-negative (e.g. `b = a = tainted`).
  Best fix is to either reject chained assignment in the parser (clear error) or
  lower it correctly in IR. Repro:
  `printf 'int main(){int a;int b;int c;c=1;a=b=c;return a;}' > /tmp/c.c && python -m securecompile_x.cli /tmp/c.c` (reports "clean", IR is wrong).
